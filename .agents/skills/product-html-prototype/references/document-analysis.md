# Document Analysis

When reading a product or design document, extract:

## Product basics

- product name
- target user
- user goal
- business goal
- core use case
- non-goals if mentioned

## Page model

- pages or screens
- navigation structure
- primary page
- secondary pages
- detail views
- settings or admin views

## Interaction model

- primary user path
- secondary user paths
- create/edit/delete flows
- approval flows
- onboarding flows
- AI generation flows
- error recovery flows

## Data model

- core entities
- important fields
- statuses
- permissions
- sample records

## UI states

- empty
- loading
- success
- error
- permission denied
- validation failure

## Assumptions

If the document omits details, infer practical defaults and write them down.
